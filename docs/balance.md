# 数值与平衡

本文记录 v11.5 的关键公式，方便后续调整。所有数值都可以在 `js/mod.js`、`js/layers/modpack.js` 中修改。

## 全局难度

```js
const DIFFICULTY_LEVELS = [0.1, 0.3, 0.5, 1, 2, 3, 4, 5]
let DIFFICULTY = new Decimal(player.difficulty)   // player.difficulty 默认 1
```

- 设置页「全局难度」在这八档之间循环，存进 `player.difficulty`，新档默认 `1.0`。
- 原版层需求与升级价格使用 `dReq()` / `upgCost()`，全部乘当前难度。
- 模组层的 `cfg.requires` 是未乘难度的原始需求，`cfg.req = cfg.requires * 难度` 是乘难度后的值，升级、设施造价与软上限都基于 `cfg.req`；改难度时 `refreshModpackReq()` 会就地重算 `cfg.req`、下一层门槛与层需求。
- 老档（版本号 < 11.3 且已有进度）按 `5.0` 保留：11.3 之前全游戏写死 ×5，直接套 1.0 会把门槛砍掉 5 倍。
- 如果想让整体更难，让玩家在设置页选更高档，或改 `DIFFICULTY_LEVELS`。

- `effect` 指数同时用于深层反哺的折算，两条公式保持一致。

## 模组层需求

第 `i` 层（从 0 开始）：

```text
requires = mpReqBase(i)              # R_i = 128 × 1.42^min(i,5) × 50^(i-5)，全程几何级数
req      = requires * 难度
exponent    = max(0.44 - i * 0.007, 0.22)   # 第 29 层 0.237；0.30 下限只在 i ≥ 36 时生效
effectExp   = max(0.06, 0.25 - i * 0.005)   # 已有点数折算成下层产量
```

- 第 0 层 `req = 128`（难度 1.0×；旧文档写 640 是难度写死 5 倍时的数）。
- 第 29 层原始需求约 4.4e43（`128 × 1.42^5 × 50^24`），乘难度后按难度倍数走。
- v11.6 断掉「木板乘回原木」：`getPointGen` 不再乘 `tmp.p.effect`，每层 `gainMult` 改吃上一层 `effect`（木板→圆石→铁→钻石→下界→末地→模组链），资源链单向、无环。树场从 `1.15^级 / 1.75^级` 改成 `1.8^级 / 1.4^级`，原木的指数引擎从回流搬到树场。仿真（`full.mjs`，seed 20260101，改这两项前）：36 层全通 5.28 小时，均 8.8 分钟。
- v11.6 修 `get cost()` 被缓存：TMT 把 getter 取到的值当静态数字存进 tmp，之后改难度不刷新，所以 ×1 与 ×5 的木斧价格完全一样。30 处层内升级改成 `cost()` 函数后实时重算（×5 下木斧 11→53、工作台 20→98）。自动化商店 `SHOP_PRICE_MULT` 2→10、`SHOP_GAIN_MULT` 20→10。
- v11.5 取消末段同档：几何级数一路走满 30 层，每层都比上一层多扛 ×50。`MP_TAIL_FROM = 36` 的指数下限在 30 层内不会触发，留作加层时的保险。
- 原曲线全程 ×1.42：30 层只从 128 跨到 e6.07，共 4 个数量级。里程碑每层给 ×15 产量，需求只涨 1.42 倍，解锁即达标。实测只点声望 9 分钟到第 21 层（血魔法），小倍率彻底压不住。改档依据是点数树一类模组树：1e13 → 1e111 → 1e150 → e78250，层与层之间是数量级关卡。
- `effectExp` 原为 `max(0.3, 0.62 - i*0.01)`。资源跨 16 个数量级后，这一项在末层能单独给出 ×250000 产量，v11.4 压到 0.25→0.06，并统一过 `chainEffect()`（1e12 以上按 log 开方）。代价是层间回馈变弱，深层产量更依赖买量与结构。
- 声望指数从 0.44 平滑降到第 29 层的 0.237；0.22 的下限只在超过 30 层后才会触发，30 个模组层内不会出现突然变平的一整段。
- v11.4 同时修了生产池：首通后本层产出改读 max(点数, 峰值)（mpGainPool）。原先读前置层点数，前置层被声望清零后整层产量归零，链在首通后停机。mpPrevPool 仍只用于门槛判定。
- v11.5 给单次声望收益封顶 `MP_GAIN_CAP = 6`：`gain = min(gain, req × 6)`。此前 `gainMult` 在深层能堆到 1e7，一次声望就把点数推到需求的 100 倍以上，门槛判定永远饱和，收入、成本、需求三者全不参与，所以任何倍率旋钮都只有 1.1× 的效果。
- v11.5 把层深减速放回自动产出：`rate /= MP_INCOME_BASE + MP_DEPTH_SLOW × i`（1.15 + 0.95i，末层约 ÷29）。封顶之后点数落回门槛以下，「本层自己产出」才成为真实的时间来源，层内买设施/升级重新有意义。
- v11.5 把层内升级的造价改成几何级数（`costs[j] = 0.011 × 2.05^j`，再乘 `MP_COST_SCALE = 3`）：十级合计 41.2 个需求，最底下一级 0.03 个需求、第十级 21 个需求。层门槛是 50 个需求，所以升级要吃本层 82% 的门槛资金：第一档便宜（先买先赚），第十档必须多刷几轮声望。旧表 `0.002 → 0.34` 合计只有 2.7 个需求，一个 tick 买完。
- v11.5 把原版六层（橡木林 / 石矿洞 / 铁矿脉 / 钻石层 / 下界 / 末地）的升级价格从写死的绝对值改成「本层门槛的比例」：`vUpg(id, frac)`，五档固定取门槛的 0.33 / 0.6 / 1 / 1.9 / 3.4 倍。木斧 1 → 5 木板、工作台 2 → 9、效率 V 40 → 51；铁矿脉五档 27 / 48 / 80 / 152 / 272 铁锭。旧数字是原版模组按「门槛 15–100」手写的，产量翻上去之后一个 tick 就买完整条树，层内没有可花钱的地方；跟门槛一起缩放后，前两档在层内早期、后两档要多声望几轮。
- 校准结果（`tools/sim/full.mjs --hours=8 --speed=10`，seed 20260101，关掉仿真代理的主动转生）：**36 层全通 5.69 小时**，均每层 9.5 分钟；末层创造 17.5 分钟，最长是铁路 42.2 分钟，最短 1–2 分钟（t/b/m/th/ae/dr/bl/fo 这几个结构层）。
  `tools/sim/curve.mjs` 那一版保留 30 层主动转生策略，记为 5.40 小时 / 35 层，用来量轮次收益。
  数值监测（`tools/sim/monitor.mjs`）：28 层的声望收益都封在需求的 6.0 倍，层内峰值 54–425 倍需求，每层升级买到 8–10 级、设施 12–16 级。

## 结构：配比型（v11.0）

5 层（工业时代 / 格雷科技 / 沉浸工程 / 核科技 / 反应堆）在原有骨架外多一层结构。参数：

| 层 | 溢价 `gain` | 上限步长 `step` | 上限封顶 `capMax` | 封顶所需设施等级 |
| --- | --- | --- | --- | --- |
| 工业时代 | 1.5 | 2.0% | 80% | 24 |
| 格雷科技 | 1.2 | 2.5% | 85% | 21 |
| 沉浸工程 | 1.8 | 1.5% | 75% | 28 |
| 核科技 | 1.5 | 2.0% | 70% | 19 |
| 反应堆 | 2.0 | 2.0% | 85% | 26 |

```text
份额 S（百分比，三道合计 100）
上限 cap_i = min(capMax, 1/3 + step × 该道设施等级)
通过 p_i   = min(S_i / 100, cap_i)
浪费 w_i   = max(0, S_i / 100 - cap_i)     // 均衡取整误差 (<1.5%) 按 0 处理
产量利用率 util = max(0.05, 3 × min(p_1, p_2, p_3))   // 均衡 1/3 时正好 1；留 5% 底，偏配到极致也不会停产
声望入账 mult  = 1 + gain × max(0, p_3 - 1/3)
实际自动产出 = 原产出 × util        // 只乘自动产出，不压低声望结算
实际声望入账 = 原入账 × mult        // 只乘结算，不回灌自动产出
```

- `util ≤ 1`（下限 0.05）且 `p_3 ≤ capMax ≤ 0.85`，所以这套结构**只会让产量打折、最多把声望入账放到 ×1.7**，不可能凭空放大数值。
- 默认 `allocMode = 0`（自动配平）→ `S = (33.3, 33.3, 33.3)` → `util = 1`、`mult = 1`，与不带结构的层完全一致；`allocMode = 1` 才读存档里的份额。
- 设施 0 级时三道上限都正好 1/3，此时任何手动偏配都会亏，这也是「先升设施再调份额」的引导。
- 手动份额按整数百分比记账（`allocShares`），点一次 +10% 从另外两道按现有比例扣，再凑满 100；`allocMode` 与 `allocShares` 都是 opt-in 的新字段，老存档由 `fixSave` 的 `fixData` 补默认值。

以工业时代（step 2%）为例，把产能压到成品上限为止（另外两道均分剩下的）时的取舍：

| 反应堆等级 | 成品上限 | 份额（原料 / 加工 / 成品） | 产量利用率 | 声望入账 |
| --- | --- | --- | --- | --- |
| 0 | 33.3% | 33 / 33 / 33 | 100% | ×1.00 |
| 2 | 37.3% | 31 / 31 / 37 | 94% | ×1.06 |
| 5 | 43.3% | 28 / 28 / 43 | 86% | ×1.15 |
| 10 | 53.3% | 23 / 23 / 53 | 70% | ×1.30 |
| 15 | 63.3% | 18 / 18 / 63 | 55% | ×1.45 |
| 24+ | 80% | 10 / 10 / 80 | 30% | ×1.70 |

表里用的是「刚好压到上限」的最优压法：再多给的份额会被上限吃掉，白扔。

## 结构：配方型（v11.1）

5 层（植物魔法 / 神秘时代 / 血魔法 / 巫术 / 新生魔艺）共用一套配方公式，每层只换参数：

| 层 | 材料 | 基础速率 | 每级生产线 | 渠道 `role` |
| --- | --- | --- | --- | --- |
| 植物魔法 | 魔力 | 0.6 / 秒 | +20% | gain（产量） |
| 神秘时代 | 灵气 | 0.6 / 秒 | +20% | points（炼成本层点数） |
| 血魔法 | 血液 | 0.7 / 秒 | +20% | unlock（解锁 12 / 13 / 18 号设施） |
| 巫术 | 咒尘 | 0.6 / 秒 | +22% | passive（自动产出） |
| 新生魔艺 | 墨汁 | 0.65 / 秒 | +20% | build（施工需求） |

```text
速率 rate    = base × (1 + step × 生产线等级)
成本 cost_i(n) = base_i × (1 + 0.5 × n)        // base = 3 / 8 / 18，n = 该档已合成次数
权重 weight  = Σ count_i × w_i                 // w = 1 / 2.5 / 6，逐档封顶 20 / 12 / 8
全满权重      = 20×1 + 12×2.5 + 8×6 = 98
carry        = max_role × weight / 98
mult         = 1 + carry                        // gain / passive / prestige
softcap      = 1 + carry                        // max_role = 0.50
build        = max(0.5, 1 - carry)              // max_role = 0.35
points 渠道   = req × 0.35 × weight / 98
```

- 三档全满的材料总量 = 345 + 360 + 396 = **1101 份**，按生产线 5 级的 1.2 / 秒算约 15 分钟；一轮里通常只吃到三到五成。
- 单份材料的效率三档基本齐平（初级 3 份换 1 权重、高级 18 份换 6 权重），所以「先喂哪条」只改变节奏，不改变终值；三档全满时 `weight = 98` 正好把 `max_role` 拿满。
- 默认 `recipeAuto = 1`、`recipeFocus = -1`：不操作也会自动合成，挂机不吃亏。自动合成每帧最多 60 次（防止长时间挂机一帧内爆掉），实际速率远达不到这个上限。
- 材料池上限 1e9（`recipeMats` 用普通 Number 存档，不用 Decimal，避免老档反序列化踩坑）。
- 进度记在 `recipeCrafts` / `recipeMats` 里；本层声望保留，更深的层声望时随 `startData` 归零。默认 `[0,0,0]` / `0` 时 `carry = 0`，所有乘区正好是 1。

## 结构：蓝图型（v11.1）

5 层（暮色森林 / 星系 / 天境 / 深渊国度 / 无尽贪婪）共用一套蓝图公式：

| 层 | 渠道 `role` | 基座格 | 初始比例 | 涨幅 | 每格 | 满图效果 |
| --- | --- | --- | --- | --- | --- | --- |
| 暮色森林 | gain | [4] | 5% | ×1.35 | 1.8% | 产量 ×1.398 |
| 星系 | prestige | [4,1] | 6% | ×1.35 | 1.8% | 声望入账 ×1.342 |
| 天境 | unlock | [4] | 5% | ×1.40 | 2.0% | 解锁 12 / 13 / 18 号设施，施工需求 ×0.84 |
| 深渊国度 | passive | [4,7] | 5% | ×1.32 | 1.8% | 自动产出 ×1.438 |
| 无尽贪婪 | softcap | [4,1,7] | 5.5% | ×1.30 | 1.5% | 软上限 ×1.380 |

```text
成本 cost(k) = req × 初始比例 × 涨幅^k          // k = 当前已点亮格数
总花费       = req × 初始比例 × 涨幅^基座格数 × (涨幅^n - 1) / (涨幅 - 1)   // n = 9 - 基座格数，基座也进指数
新连线 newEdges = 当前连线 - 基座自带连线
mult        = (1 + u × newEdges) × (完成 ? 完成奖励 : 1)
build       = max(0.4, 1 - u × 新点亮格数 - (完成 ? 0.1 : 0))   // 预留的 build 渠道，暂无层使用
天境（unlock）= max(0.5, 1 - 0.02 × 新点亮格数)                  // 全亮 ×0.84
```

- 九宫格 12 条边（横 6、竖 6）。**基座格**（`seed`）免费亮着、计入连线判定，但 `newEdges` / `新点亮格数` 都减掉基座的部分，所以一格没点时 `mult` 正好是 1 —— 这是老存档与本轮重置后的基线。
- 全图总花费：暮色森林 ≈1.93 倍需求、星系 ≈2.24、天境 ≈2.41、深渊国度 ≈1.63、无尽贪婪 ≈1.54（合计材料数 1238 / 11757 / 6961297 / 49341 / 18120154）。量级在「两次声望的入账」上下，买图确实会让声望晚一点。
- 完成奖励：gain ×1.15、passive ×1.20、prestige ×1.12、softcap ×1.20、build −0.1。
- 花的是本层点数（`player[层].points`），不存在额外资源；`blueCells` 是 9 个 0/1，存普通数组，老档由 `fixSave` 补齐。和点数同命：本层声望保留，更深的层声望时随 `startData` 归零。
- 天境是 `unlock` 渠道：5 格开 12 号设施、7 格开 13 号设施、全亮开 18 号主题核心，同时每点亮一格把施工需求再压 2%（最多 −16%）——它不直接给乘区，但能把这一层的设施门槛绕过去。

## 结构：市场型（v11.2）

5 层（等价交换 / 林业 / 神秘农业 / 实用存储 / 末影接口）共用一套市场公式，每层只换参数：

| 层 | 渠道 `role` | 周期 | 振幅 | 手续费 | 一手宽 | 满进度效果 |
| --- | --- | --- | --- | --- | --- | --- |
| 等价交换 | gain | 84 秒 | 32% | 5% | 需求 5% | 产量 ×1.40 |
| 林业 | passive | 108 秒 | 26% | 5% | 5% | 自动产出 ×1.40 |
| 神秘农业 | points | 72 秒 | 34% | 4% | 4% | 本金退回 + 差价入账，满进度 0.35 倍需求 |
| 实用存储 | unlock | 96 秒 | 28% | 5% | 5% | 40% / 70% / 100% 开 12 / 13 / 18 号设施，施工需求 ×0.80 |
| 末影接口 | build | 120 秒 | 24% | 5% | 5% | 施工需求 ×0.65 |

```text
price_i(t)  = 1 + amp × sin(2π × t / period + i × 2π/3)      // i = 0,1,2，三种货相位差 120°
cost_i      = req × spread × price_i                        // 买入一手
profit_i    = max(0, (price_now - 均价) × req × spread × 持仓手数)
profit      = min(req × cap, profit + profit_i)              // 累计、封顶
prog        = profit / (req × cap)
mult        = 1 + MAX[role] × prog                           // build / unlock: 1 - MAX × prog
```

- `t`（`mktT`）只在层已解锁时累加，锁着的层不推进时钟，进度永远是 0。
- 默认 `cap = 0.35`：满进度要赚到需求的 35%。一手的手续费是需求的 5%，单程价差最大 2 × amp（等价交换 0.64），所以**一次完美的低买高卖只赚到需求的 3.2%**，满进度要约 11 次完美往返 —— 这是一个「愿意盯盘才有收益」的设计，不盯盘就是 0。
- 单笔收益不足以封顶，但 `min(cap, ...)` 保证无论来回刷多少次，进度也不会超过 100%，换来的加成不会超过这一层的上限。
- 非点数线的本金不退（点数被消耗掉），所以市场是**点数黑洞**：冲声望前买卖会把声望门槛往后推。神秘农业（`points`）例外——本金原样退回、只把差价记成本层点数，它的作用是「用小额点数换大额点数」，满进度约 0.35 倍需求，但仍然受封顶约束。
- 状态：`mktT`、`mktHands[3]`、`mktBasis[3]`、`mktProfit`，都是普通数字 / 数组，老档由 `fixSave` 补齐。与点数同命：本层声望保留，更深的层声望时归零。
- 默认（0 手）`profit = 0` → 所有乘区 ×1，与 v11.1 的数值完全一致。

## 结构：网格型（v11.2）

5 层（应用能源 / 龙之研究 / 超能物质 / 环境科技 / 铁路）共用一套网格公式：

| 层 | 渠道 `role` | 上限模块 | 每格价格 | 涨幅 | 满进度分数 | 满进度效果 |
| --- | --- | --- | --- | --- | --- | --- |
| 应用能源 | gain | 9 | 4.5% | ×1.20 | 15 | 产量 ×1.40 |
| 龙之研究 | prestige | 7 | 5.5% | ×1.24 | 12 | 声望入账 ×1.40 |
| 超能物质 | softcap | 8 | 5.0% | ×1.22 | 14 | 软上限 ×1.50 |
| 环境科技 | passive | 8 | 5.0% | ×1.21 | 13 | 自动产出 ×1.40 |
| 铁路 | build | 9 | 4.5% | ×1.19 | 15 | 施工需求 ×0.65 |

```text
cost(k) = req × price × growth^k          // k = 已摆模块数（不含基座）
score   = node × 新模块数 + edge × 新连对数 // node = 1、edge = 2
prog    = min(1, score / target)
mult    = 1 + MAX[role] × prog             // build: 1 - MAX × prog
```

- 4×4 = 16 格，相邻只算上下左右（横 12 条 + 竖 12 条，共 24 条可能的边）。
- 8 个模块最好的摆法能凑出 10 条边（2×4 的矩形），score = 8 + 20 = 28，远超 target；实际上一半的板子就够满进度，剩下的格子是留给「懒人摆法」的容错。
- 摆满各层上限的总花费：应用能源 9 格 ≈ 0.94 倍需求、龙之研究 7 格 ≈ 0.79、超能物质 8 格 ≈ 0.89、环境科技 8 格 ≈ 0.86、铁路 9 格 ≈ 0.90（`Σ req × price × growth^k`，k = 0…上限-1）。比蓝图（1.5–2.4 倍）便宜，比配方（主要花时间）贵。
- 上限模块数（7–9）比 16 格少，意味着**不可能全摆满**，必须在「多一个模块（+1 分）」和「多一条连线（+2 分）」之间取舍。
- 状态：`gridCells` 是 16 个 0/1，普通数组。与点数同命：本层声望保留，更深的层声望时归零。
- 默认（0 格）`score = 0` → 所有乘区 ×1。

## 结构：节奏型（v11.2）

5 层（冰与火 / 虚无世界 / 匠魂 / 热力膨胀 / 创造模式）共用一套节奏公式：

| 层 | 渠道 `role` | 圈长 | 窗口 | 命中上限 | 满命中效果 |
| --- | --- | --- | --- | --- | --- |
| 冰与火 | gain | 6.0 秒 | 24% | 8 | 产量 ×1.40 |
| 虚无世界 | prestige | 7.0 秒 | 22% | 7 | 声望入账 ×1.40 |
| 匠魂 | passive | 5.0 秒 | 26% | 8 | 自动产出 ×1.40 |
| 热力膨胀 | unlock | 5.5 秒 | 24% | 8 | 40% / 70% / 100% 开 12 / 13 / 18 号设施，施工需求 ×0.80 |
| 创造模式 | softcap | 6.5 秒 | 22% | 8 | 软上限 ×1.50 |

```text
phase    = (t mod period) / period
inWindow = |phase - 0.5| ≤ window / 2
命中      : hits = min(hitsMax, hits + 1)
失误      : hits = max(0, hits - 1)         // 窗口外点击
点击间隔  : ≥ lock（0.28–0.30 秒），间隔内的点击直接忽略
prog     = hits / hitsMax
mult     = 1 + MAX[role] × prog             // build / unlock: 1 - MAX × prog
```

- 不花资源，只花注意力。窗口宽度 22%–26% 圈长，也就是一圈 5–7 秒里约 1.1–1.7 秒是有效区间。
- 失误掉 1 命中、命中加 1，一次失误抵掉一次命中；点击间隔 0.28–0.30 秒，一圈最多敲进 3 下，命中上限 7–8 次大约 3 圈（15–20 秒）就能满档。v11.2 原为 14–16 次、失误 −2，实测太耗注意力，v11.3 砍半。
- 状态：`rhyT`、`rhyHits`、`rhyLast`，普通数字。与点数同命：本层声望保留，更深的层声望时归零。
- 默认（0 命中）`prog = 0` → 所有乘区 ×1。

## 深层反哺（基础产量）

第三层起，每层的 `everBest`（历史最高资源）会给原木基础产量提供永久加成：

```text
layerBonus = (everBest + 1) ^ (effectExp × 0.15) - 1
depthMult  = 1 + Σ layerBonus
每秒原木   = (基础产量 + 树场 × 2) × 1.8^树场级 × depthMult × 全局倍率
```

- `everBest` 单独记录，`layerDataReset` 不会清空，因此声望、级联重置与挑战都不会让深层加成失效。
- 各层加成线性相加而不是连乘：30 个模组层同时达到 1e6 资源时 `depthMult` 约为 60，不会把基础产量直接推到天文数字。
- 原版第三层起同样参与（i/d/n/e 的 effectExp 为 0.5/0.6/0.6/0.7，与各层 effect 指数一致）；木板 effect 只乘圆石、不乘原木（v11.6 起资源链单向），所以原木产量里不含木板 effect，也不重复计入。
- 顶部 HUD 只在 `depthMult > 1` 时挂出「深层反哺 ×N」标签。

## 首通施工

```text
need     = req * arch.time * 折扣
进度     = clamp(投入材料 / need, 0, 1)
收益系数 = 0.3 + 0.7 * 进度
```

- 材料来自上一层资源（`cfg.prev` 的 `points`），按 25% / 50% / 全部剩余 三档投入，最后一档自动补足；投入量记在 `player[层].construct`。
- 原型施工需求倍率：采集 0.9、科技 1.1、魔法 0.9、工业 1.0、探索 1.2。
- 25 号升级：`need *= 0.8`。
- 施工设施每级减少 3.85%（`0.5 / 13`），最多 13 级，第 13 级正好减少 50%。
- 主题特性「疾行」与主题核心（疾行类）：乘 0.92 / 0.985^级，6 号里程碑把特性折扣平方。
- 探索路线与 5 号里程碑：快路线减需求效果从 40% 提高到 60%；丰路线 `need *= 1.4`。
- 8 号里程碑（主题核心为疾行类）：`need *= 0.95`。
- 挑战只影响声望收益、软上限、自动产出与特性/核心，不改变施工需求。
- 施工未满也能提前声望，声望入账在软上限折算后再乘 `mpBuildGainMult()`，向下取整；满额 ≥1 时结果保底 1，避免提前声望拿 0。折扣只作用于声望结算（`game.js` 的 `doReset` 调用层的 `prestigeGainMult()`），`getResetGain()` 保持满额供层内自动产出使用。
- `canReset()` 只检查前置资源 ≥ `req` 且本次收益 ≥1；首通（`prestiged === false`）时前置资源取 `mpPrevPool(cfg)` = `max(本轮峰值 best, 当前点数)`，`baseAmount()` 与 `getResetGain()` 同口径，首通后回落到当前点数；首通只看「池 ≥ 需求」，收益 ≥1 从第二次起才要求（`gainMult` 与指数会把有效门槛抬到约 1.7× 需求）；`mpBuildProgress()` 负责进度，`mpBuildDone()` 等价于进度满 100%。
- 每层首次声望后记为已通过（`player[层].prestiged`），此后该层不再检查施工、收益固定 100%；重置时保留这个标记，`construct` 随 `startData` 归零。
- 自动声望通过层的 `autoPrestigeReady()` 钩子等本轮施工完成才触发，不会为了提前收益主动重置。
- 施工没有跳过手段：v8.6 起移除了「施工券」，唯一的推进方式是投入上一层资源。投入会占用声望本金，声望本身仍要求上一层资源 ≥ `req`，投入后记得留足。
- 本轮第一次投满时记 `player[层].buildBonus`，声望收益额外 ×1.25；掉进度（押注失败）后这条奖励失效，需重新投满。

| --- | --- |

```text
每 3 次点击 +1 层，每层全局产量 +15%，最多 5 层（+75%）
30 秒不点击清零（按真实时间）
```

- `clickSpeedMult() = min(10, sqrt(player.devSpeed))`，只在控制台调过加速时生效，正常游玩恒为 1。

### 裂隙（限时事件）

| 类型 | 90 秒内目标 | 奖励 |
| --- | --- | --- |

### 施工分档与首满

- 投入按钮 25% / 50% / 全部剩余 三档（12 / 14 / 15 号 clickable），最后一档按剩余需求补足。
- 本轮第一次投满时置 `player[层].buildBonus`，声望收益额外 ×1.25。
- `prestigeGainMult() = 施工折扣 × 专精声望 × 首满 1.25 × 世界词条`，且首满那一项要求 `mpBuildDone()` 仍为真：押注失败把进度打到 85% 后，1.25 与满额收益一起消失。

### 押注（每层每轮一次）

```text
胜率 p   = 0.5 + 0.05 × 本层已完成挑战数（0–3，最高 0.65）
押注额   = min(上一层资源 × 30% / 60% / 100%, 上一层资源 − req)（向下取整）
赢       = 拿回 1.2/p 倍押注 + 施工进度 +10% 需求
输       = 押注归零 + 施工进度 −15% 需求（不低于 0）
期望     = p × 1.2/p − 1 = +20%
```

- 写在 `player[层].wagerUsed / wagerResult`，随 `startData` 每轮清零；`prestiged` 或挑战进行中不能押。
- v9.1 起押注额带保底：`mpWagerStake()` 把上限压到「本金 − req」，押完一定还够声望；本金本身没超过 `req` 时三个押注按钮直接不可点，卡片显示「留足声望需求后没有可押的余量」。赌的刺激保留在胜负，不再保留在「把自己押到卡死」。

## 软上限（收益递减）

本层资源没有存储上限，唯一的天花板是声望收益的软上限。

```text
softcap = req * arch.soft
```

| 原型 | soft 倍率 |
| --- | --- |
| 采集 | 0.14 |
| 科技 | 0.10 |
| 魔法 | 0.19 |
| 工业 | 0.15 |
| 探索 | 0.26 |

再乘：

- 2 号里程碑：softcap ×2。
- 23 号升级：softcap ×1.5。
- 上限设施（13 号）：每级 softcap +15%。
- 主题特性「稳固」与主题核心（稳固类）：×1.20 / ×1.06^级，6 号里程碑把特性部分平方。
- 科技「存储研究」：每级 +10%；探索「稳」路线：×1.25（5 号里程碑 1.375）。
- 当前挑战为薄雾时：×0.5；12 号挑战完成：×1.25。
- 8 号里程碑（主题核心为稳固类）：×1.2。
- 层机制：轮转、过载等按当前状态乘进软上限（见「层机制」一节）。

声望收益一旦超过软上限，超出部分按平方根折算。软上限只压缩单次声望的战利品，不限制 `points`、`best` 或累计资源，因此可以一直堆下去，只是越堆越慢。

## 重置范围

- 单次声望最多回退本层及下面 2 层（`RESET_DEPTH = 3`，`js/game.js` 的 `doReset`），更低的层与它们的点数、购买项、升级保持原样。
- 发起声望的本层不重置点数与升级，只把 `resetTime` 归零；点数、升级、设施被清空的是窗口内的更低层。
- 例如手动重置第 6 层会回退第 4–5 层，木板（第 0 层）、圆石（第 1 层）、铁（第 2 层）与原木 `player.points` 都保留；手动重置第 5 层则回退第 3–4 层。
- 每次声望会把回退下限写入 `player.resetFloor`；自动声望不会低于该下限（`autoResetFloor`），保留层不会被逐 tick 连锁重置，想重置更低层需手动声望。
- 第一层「橡木林」豁免：`autoResetFloor` 对 `row 0` 直接返回 0，`doReset` 里 `floorExempt` 的自动分支也不改写 `player.resetFloor`。所以深层的下限抬到 1 以上之后，木板照样会自动转换，同时不会把深层刚抬起来的下限抹平；第二层及以下仍按下限暂停。
- 挑战完成判定同样只在回退窗口内执行，窗口外的挑战不会被顺带完成。
- 窗口内已首通层仍由 `retainStartKit` 保留 12 号升级与 1 级生产设施。

## 声望收益

```text
gain = (前置资源 / req)^exponent
     * gainMult^gainExp
```

随后：

```text
if (gain >= softcap) gain = sqrt(gain) * sqrt(softcap)
gain = floor(gain)
```

`gainMult` 的来源：

- 11 号升级：×arch.upg2（2 / 2.5 / 3）。
- 13 号升级：×arch.upg3（3 / 4）。
- 15 号升级：主题签名倍率 ×`sig.mult`（7–10），逐层不同。
- 24 号升级：本层 ×1.5（同时解锁上限设施）。
- 0/3/4 号里程碑：本层各 ×1.5；7 号里程碑再 ×2；9 号里程碑（完成全部挑战）再 ×1.5。
- 增益设施：每级 ×arch.gain（1.08–1.15），最多 20 级。
- 21 号升级：全局产量 **+10%**（30 层全部购买后为 ×4，线性叠加，不再逐层相乘）。
- 下一层的 `effect()`：`(下一层资源 + 1)^effectExp`。
- 主题特性与原型机制（见下两节）；6 号里程碑使特性效果翻倍。
- 主题核心：按 `cfg.trait.core` 生效——产量/自动产出类每级 ×1.08，软上限类 ×1.06，施工需求类 ×0.985，全局产量类每级 +0.5%（线性叠加）；8 号里程碑再按核心类型给 ×1.25 / ×1.2 / ×0.95 / ×1.2 / +2%。
- 11 号挑战完成：本层 ×1.5。
- 层机制：专属或模板机制按当前状态乘进产量（见「层机制」一节）。
- 全局成就与旧层加成。

## 原型机制

| 原型 | 机制 | 数值 |
| --- | --- | --- |
| 采集 | 连续采掘 | 自动产出 ×`1 + 2 × 施工进度`；5 号里程碑把系数 2 提高到 3 |
| 科技 | 研究分支 | 算力：声望 +10%/级；存储：软上限 +10%/级；散热：自动 +15%/级；各 5 级 |
| 魔法 | 主动咒语 | 消耗 10% 资源，60 秒内 `gainMult ×5`，冷却 8 分钟（5 号里程碑 6 分钟） |
| 工业 | 设施联动 | 声望 `×(1 + 0.01 × (生产等级 + 上限等级))`；自动 `×(1 + 0.02 × 增益等级)`；5 号里程碑两项 +50% |
| 探索 | 远征路线 | 快：施工需求 ×0.6、收益 ×0.8；稳：软上限 ×1.25；丰：施工需求 ×1.4、收益 ×1.3；5 号里程碑使正向部分 +50% |

科技研究点按「前置资源超出需求的比例」计算：`1 + floor(5 × min(1, 前置资源 / req - 1))`，即每超出 20% 多 1 点，每次声望 1–6 点；5 号里程碑再 +1，最多 7 点。研究与路线状态写在 `player[层].research` / `player[层].route`，魔法计时写在 `spellUntil` / `spellReadyAt`；所在层被重置时随 `startData` 归零。

每层在原型机制之外还有 1 套层机制，全部乘进 `gainMult`、`passiveGeneration`、`mpSoftcap` 或 `mpBuildNeed`。前 6 层专属：

| 层 | 机制 | 数值 |
| --- | --- | --- |
| 暮色森林 | 迷宫探索 | 每次投入 12% 当前资源，最多 12 层：产量 ×`1 + 0.04 × depth`，自动 ×`1 + 0.02 × depth`，软上限 ×`1 + 0.01 × depth` |

## 挑战

| 条件 | 挑战期间 | 目标 |
| --- | --- | --- |
| 薄雾 | 软上限 ×0.5 | 1.0 × req |
| 断供 | 自动产出 ×0.25 | 1.5 × req |
| 迟滞 | 声望收益 ×0.6 | 1.2 × req |

### 挑战总览（v10.0）

层内奖励是 90 个分散的静态乘数，玩家看不出总量，所以另加一条全局：

```text
全局产量倍率 = 1 + 0.005 × 已通关挑战数 + 0.05 × floor(已通关挑战数 / 10)
满 90 个     = 1 + 0.45 + 0.45 = ×1.9
```

- 走加法（与层间任务、记忆洪流同口径），不连乘；30 个时 ×1.3，60 个时 ×1.6，90 个时 ×1.9。
- 每完成一个挑战，层内已有的奖励（11 号产量 ×1.5、12 号软上限 ×1.25、13 号自动 ×1.5、9 号里程碑 ×1.5、共鸣 ×1.06–1.12/个、押注胜率 +5%）都不变，这条只是额外叠加的汇总进度。
- 完成数每轮真转生后清零（`prestiged`、`challenges` 随层重置），所以它是「本轮进度」而不是永久加成。
- 科技树页底部的「挑战 n / 90 · 全局产量 +x%」直接读 `challengeClearedTotal()` / `challengeGlobalBonus()`，与倍率同源。

任务不单独存完成标记，每个任务的目标都从只增不减的存档状态推导：

| 任务 | 数据来源 | 目标 | 奖励 |
| --- | --- | --- | --- |
| 初见模组海 / 五层连穿 / 十层工业带 / 二十层远征 / 三十层全图 | `player[层].prestiged` 计数 | 1 / 5 / 10 / 20 / 30 | +4% / +6% / +8% / +10% / +12% |
| 挑战者 / 挑战收割机 | `challenges[11..13]` 已完成的槽位数 | 10 / 40 | +4% / +6% |
| 单层全清 / 五层全清 | 3 个挑战全部完成的层数 | 1 / 5 | +5% / +8% |
| 自动化网络 | `player.shop.owns` 中已购买的层数 | 10 | +6% |
| 深层回响 | `depthBaseMult()` | ×2 | +5% |
| 声望长跑 | `player.quests.stats.prestiges` | 100 | +8% |
| 模组海征服者 | 以上 12 个任务的完成数 | 12 | +10% |

已完成任务的奖励线性相加，由 `globalProductionMult()` 末尾乘入：

```text
全局倍率 = (原本各来源的乘积) × (1 + Σ 已完成任务奖励)
```

- 全部完成合计 **+92%**，作为一次乘算；不会像 21 号升级那样逐层叠乘。
- 声望计数只在真实声望时 +1（`onPrestige`），挑战进入与退出不计入；旧存档首次载入按已首通模组层数回填一次。
- 其余任务目标均为单调状态，声望与级联重置不会让进度或奖励回退。

## 转生（模组记忆）

首通 20 个模组层后，侧栏解锁「模组记忆」（打通 30 层才能真转生）。转生是第二层循环：清空数值进度，把累计声望换成永久记忆升级。

```text
总记忆   = 已冻结轮数 × 10 + 本轮已赚（期中 5 / 全通再 5）
本次可领 = 总记忆 - 已领取
可用记忆 = 已领取 - 已投入
```

- 每轮 10 点分两笔（v10.1 起）：
  - **期中 5 点**：本轮已首通 20 层 **且** 本轮声望满 50 次。可以单独领（`rebirthCollectStage()`），不重置进度。
  - **全通 5 点**：30 层全部首通后随真转生一起领（`rebirthClaim()`），同时轮数 +1。
- 期中为什么必须绑 20 层：只绑声望的话，开局自动声望刷 50 次只要几分钟，领 5 点 → 真转生 → 再刷 50 次，一小时就能把 736 点刷满。两个条件同时满足，声望才真正跟进度绑在一起。
- 期中为什么是 20 层而不是 15 层：15 层的兑换率是 `5/15 ≈ 0.33 点/层`，与打穿一轮的 `10/30 ≈ 0.33` 完全相同，玩家会算出来「打一半就重置」更划算；20 层是 `0.25 点/层`，明显低于全通，没有刷半轮的动力。
- 总额上限被锁死在 `rounds × 10 + 10`：期中先领之后，本轮剩下的 5 点只在打穿时才补，任何「领了重置再领」的循环都不会多出点数（`claimed` 只增不减，`total` 只由轮数与当前轮进度决定）。
- 记忆页在首通 20 层就先露出来（此时只能领期中），打通 30 层才能真转生；解锁条件仍是「20 层首通 **或** 已领过记忆」，否则真转生清掉 `prestiged` 后记忆页会消失。
- **真转生**：v8.6 起除模组记忆层外，所有层（含成就、层间任务、商店）全部回到 `startData` —— 资源、升级、设施、研究、路线、法术、层机制、首通标记 `prestiged`、`everBest` 与 `player.resetFloor` 一并清零，从 `getStartPoints()` 的原木重新开始。
- 因为层间任务会被清空，累计声望额外记一份基线 `player.rebirth.basePrestige`：`rebirthPrestigeCount() = basePrestige + quests.stats.prestiges`，领取时把当前值写回基线 —— 这份计数现在只用于展示与统计，记忆总额按轮数 + 本轮分期算，同样只增不减。
- 转生后不再有「已首通但本轮未施工」的状态（`prestiged` 已清零），原先的熟路减半（`REBIRTH_WALL_MULT`）不再生效；施工需求只会被 25 号升级、施工设施与「记忆熟路」降低。
- `construct` 随 `layerDataReset` 归零；施工不依赖时间，重建速度取决于投入材料的速度。
- 领取与购买都只增不减：记忆不会因转生减少，升级也不随转生重置。

### 封顶折扣（v10.2）

```text
折扣       = min(10%, floor(上一次真转生时的本轮声望 / 100) × 1%)
实付价     = ceil(整条轨道累计原价 × (1 - 折扣)) - ceil(截止上一级的累计原价 × (1 - 折扣))
八条全满   = 736 点 → 667 点（封顶时实测省 9.4%）
```

- 折扣在**真转生那一刻**按「刚打完这一轮」的声望冻结，下一轮一直有效。购买基本发生在转生之后，那时本轮声望已经清零 —— 实时按当前声望算的话永远是 0%，等于没有这个折扣。
- **按整条轨道的累计价取整**，不是每级单独 `ceil`：逐级取整时小额价格被 `ceil` 吃掉大半折扣（封顶档实测只省 **5.6%**），按累计价取整才能让「−10%」名副其实。最便宜的一两级本来只有 2–3 点，抹零后看不出变化，卡片只在真的便宜了的那一级显示原价。
- `player.rebirth.spent` 按**实付**累计。不能用「按当前等级回算原价」那一套：打折买下的等级会在折扣消失后把「已投入」抬高，可用记忆随之回缩。
- 上限 10% 是刻意的：736 → 667 只等于少跑 7 轮（74 → 67），不改变「打通几轮」这条主线，也不至于把小折扣做成永久乘区。

折扣档位与满配总价（八条线全买满，实付合计）：

| 本轮声望 | 折扣 | 全满实付 | 等效轮数 |
| --- | --- | --- | --- |
| 0–99 | 0% | 736 | 74 |
| 500 | 5% | 703 | 70 |
| 900 | 9% | 674 | 67 |
| 1000+ | 10% | 667 | 67 |

单轮声望没有上限：全通之后继续滚声望再去转生，1000 次是能做到的，所以封顶折扣不算难拿 —— 难点仍在轮数，八条线全买满的缺口不会因为折扣消失。

| 升级 | 每级效果 | 级数 | 造价 |
| --- | --- | --- | --- |
| 记忆洪流 | 全局产量 +10%（加法） | 10 | `2 × 1.45^level` |
| 记忆扩容 | 模组软上限 ×1.06 | 8 | `2 × 1.45^level` |
| 记忆起手 | 转生后每层直接给 1 级生产设施 + 12 号升级 | 6 | `2 × 1.45^level` |
| 记忆捷径 | 自动声望收益 ×1.10/级（最高 ×2.0） | 10 | `2 × 1.45^level` |
| 记忆熟路 | 施工需求 −6% | 8 | `2 × 1.45^level` |
| 记忆丰产 | 模组层声望收益 ×1.15 | 8 | `2 × 1.45^level` |
| 记忆自动 | 模组层自动产出 ×1.25 | 6 | `2 × 1.45^level` |
| 记忆深潜 | 深层反哺指数 +0.02 | 6 | `2 × 1.45^level` |

- 单条线造价合计：10 级 291 记忆，8 级 120 记忆，6 级 49 记忆；八条线全部升满需要 **736 记忆**（v9.1 起价格曲线由 1.55 放缓到 1.45）。折扣封顶时实际只要 **667 记忆**（约 −9.4%），等于少跑 7 轮。
- 记忆洪流乘进 `globalProductionMult()`，自身 10 级提供 +100% 的加法内部倍率。
- 记忆扩容乘进 `mpSoftcap()`，只影响模组层。
- 记忆起手只在转生重置时发放生产设施等级；之后正常声望仍按原有启动套件保留 12 号升级与 1 级生产设施。
- 记忆捷径只放大自动声望那一次的声望入账（`doReset` 的 `auto` 分支），不改变手动声望、商店价格、自动购买或回退下限；阈值固定 1.5×，因为把阈值压到 1.0× 等于把每次收益压到刚好 1 点，是负收益。
- 记忆熟路乘进 `mpBuildNeed()`，与 25 号升级、施工设施同为乘法折扣，三者叠满约剩 `0.8 × 0.5 × 0.52 ≈ 21%` 需求。
- 记忆丰产乘进模组层的 `gainMult()`，记忆自动乘进 `passiveGeneration()`，都只作用于模组层，不影响原版六层。
- 记忆深潜加在 `computeDepthBaseMult()` 的指数上（`exp + 0.02 × 级数`），满级把 30 层的反哺斜率整体抬高约 13%。
- 记忆总额为 `已冻结轮数 × 10 + 本轮已赚`（v10.1 起分期；v9.9–v10.0 为 `轮数 × 10`；v9.1–v9.8 为 `floor(累计模组声望 ^ 0.6 × 2)`）：一轮 = 30 个模组层全部首通一次，期中与全通两笔加起来仍是每轮 10 点，所以记忆只跟「打通几轮」有关，跟挂机多久、自动声望刷了多少次无关 —— 旧公式把自动声望也算进累计次数，全自动挂 5–10 小时就能刷满 736 点。第 1 轮 10 点（5 级）、第 10 轮 100 点（26 级）、第 30 轮 300 点（47 级）、第 74 轮 740 点（62 级全满）；想更硬把 `REBIRTH_MEMORY_PER_ROUND` 调小即可（7 → 30 轮 40 级、106 轮满）。

## 升级与设施造价

升级造价：

```text
cost = req * factor * arch.cost * (trait.upgrade ^ (6 号里程碑 ? 2 : 1))
factor = [0.002, 0.004, 0.008, 0.015, 0.03, 0.05, 0.09, 0.14, 0.22, 0.34]
```

升级造价是函数，6 号里程碑会实时把「博学」类折扣翻倍。

设施造价：

| 设施 | 基础系数 | 增长 | 上限 |
| --- | --- | --- | --- |
| 生产 | 0.01 × req | 1.8^level | 无 |
| 增益 | 0.02 × req | 1.9^level | 20 |
| 上限（软上限） | 0.03 × req | 2.0^level | 无 |
| 施工 | 0.04 × req | 2.1^level | 13（降低施工需求最多 50%） |
| 主题核心 | 0.05 × req | 2.2^level | 10 |

增益设施最多购买到 20 级（`Decimal.pow(arch.gain, min(level, 20))`），避免单层声望倍率无限叠乘；施工设施最多 13 级，降低施工需求的效果在 50% 封顶。「工程」类特性会乘进所有设施造价，6 号里程碑同样翻倍。

科技层的 15–17 号研究分支不花本层资源，改用研究点：每级成本依次为 1、2、3、4、5 点，最多 5 级。

## 自动化产出

```text
passive = 生产设施等级 * arch.passive
        * (14 号升级 ? 1.5 : 1)
        * (1 号里程碑 ? 2 : 1)
        * 特性/主题核心的自动产出倍率
        * (13 号挑战完成 ? 1.5 : 1)
        * (当前挑战为断供 ? 0.25 : 1)

每秒实际产出 = passive * 本层声望收益（resetGain）
```

`passive` 只是系数，`generatePoints` 会再乘一次当前的声望收益，所以设施产出的真实速度与声望收益同步增长；界面显示的每秒产出就是乘完后的数值。

原型的 `passive`：采集 0.06、科技 0.04、魔法 0.06、工业 0.05、探索 0.04。

## 自动化阈值与启动套件

```text
自动声望条件：canReset && baseAmount ≥ autoPrestigeMult() × requires
autoPrestigeMult() = 1.5（固定）
每个 tick 最多自动声望一次
```

- 默认阈值常量是 `js/game.js` 中的 `AUTO_PRESTIGE_MULT = 1.5`，经 `autoPrestigeMult()` 读取；调高常量会让自动声望等到更多资源，调低则更频繁地重置但每次收益更少（收益按 `(资源/需求)^指数` 计算，早重置是负收益）。「记忆捷径」改为给自动声望乘 `1 + 0.1 × 等级`，不再动阈值。
- 自动声望受商店顶部的总开关 `player.shop.autoPrestige` 控制；任意挑战进行中跳过。
- **末段让位**：模组层 `autoPrestigeReady()` 除了要求本轮施工完成，还会在「下一层已解锁但还没首通，本层池（`max(points, best)`）没到下一层门槛，且重置后的收益比现在持有还少」时返回 false。原因是自动声望会把本层点数清零，而下一层首通的门槛正好按本层点数算（前中段约 1.42 倍本层需求，现在全程几何级数（每层 ×50），末段不再同档）；不让位的话自动化会反复清掉要用的门槛资源，末段（27 实用存储 → 28 铁路）攒不出来。早段重置后点数比现在多，属于正常涨法，校核里不拦。手动声望不受影响，下一层首通后自动恢复。
- 已首通层被回退时，`retainStartKit` 会保留 12 号升级与 1 级生产设施，避免每次重置后重新买第一级。
- 自动化价格在 `js/layers/shop.js` 的 `SHOP_PRICE_MULT = 2`；改这个值即可整体调整自动化造价。

## 调整建议

- **想更快**：降低 `requires` 的底数 128，或提高 `arch.passive` / `arch.gain`。
- **想更慢**：提高 `DIFFICULTY`、降低 `exponent`、调高施工需求系数 `MP_BUILD_RATIO`。
- **想更强调收益递减**：降低 `arch.soft` 或 `softcapPower`（当前固定 0.5）。
- **想整体调快 / 调慢**：`MP_DEPTH_SLOW` 是一阶旋钮，每 ±0.1 约换 ±15 分钟全链时长；`MP_INCOME_BASE` 管早段，`MP_DEPTH_SLOW` 管末段。
- **层内太松**：把 `MP_GAIN_CAP` 压到 3–4；调回 10 以上会退回到封顶前「一次声望跨两层」的老问题。
- **想压缩层数**：减少 `MOD_THEMES` 条目即可，工厂与成就会自动适配。

修改后建议至少验证：

1. 第一层能否在投入材料完成施工后正常声望。
2. 软上限是否只压缩单次声望，而不阻止 `points` / `best` 继续增长。
3. 下一层是否自动解锁。
4. 成就墙数量是否仍与 `ACH_TOTAL` 一致。

## v11.7 全量数值重算（`js/balance-spec.js`）

数值入口不再散在各层文件里，全部收敛到 `js/balance-spec.js` 的 `BAL`：`vUpg()`、`mcBuyCost()`、六层 `requires`、模组层 `cfg.req` / `cfg.nextReq`、`getResetGain()` 的收益上限都从这里取值。调平衡只改这一个文件。

| 参数 | 值 | 作用 |
| --- | --- | --- |
| `modCostScale` | 3 → **12** | 模组层十档升级的总价系数，整条升级链贵 4 倍，层内必须攒钱 |
| `modGainCap`（原 `MP_GAIN_CAP`） | 6 → **4** | 单次声望入账 ≤ 当前需求 × 4，刷一轮跳几层的情况消失 |
| `gainCap` | **6** | 原版层的同口径上限（`getResetGain` 里统一裁） |
| `vanillaUpgScale` | **1** | 原版升级价保持原样，见下方说明 |
| `facility` / `modFacility` | 原值 | 设施底价与涨价逐层列出，方便单独调 |
| `reqGrowVanilla` / `reqGrowMod` / `reqCountCap` | 1 / 1 / 0 | 需求随声望次数增长的旋钮，当前关闭 |

**为什么原版六层不动**：早期收入极紧（木板每分钟个位数），升级价整体乘 2.4 后实测 12 小时只过 1 层，直接锁死。原版的「钱不够花」由设施涨价与收益上限保证，抬价只会把开局堵死。

**校准**：`node tools/sim/full.mjs --hours=14 --speed=10`（seed 20260101，关掉代理主动转生）—— **36 层全通 8.79 小时**，均每层 14.6 分钟，末层 29.0 分钟。改前同一脚本 4.53 小时。

`reqGrow*` 那一组是为「只点声望不买升级」预留的刹车：打开后本层每声望一次，下一次需求乘 `grow`（上限 `reqCountCap` 次），被上层级联重置时计数归零。当前取 1 表示不启用。
### 解锁门槛（v11.7.1）

原版 s / i / d / n / e 五层改为「上一层买够 2 档升级才解锁」（`BAL_UNLOCK_MIN`），判定在 `layers[id].unlocked()` 里，每帧重算；`p` 不设门槛。

这条规则是为了堵「只点声望、不买升级也能一层层过关」：声望只产出货币，不解锁下一层，钱必须花在升级上才算推进。仿真里代理本来就见啥买啥，所以曲线不变（8.79 小时 / 36 层）。

**为什么不用另外两种写法**：

- 需求随声望次数增长（`reqGrow*`）：实测会把开局锁死。每层都是下一层的货币来源，抬高本层门槛等于掐住下一层的收入，12 小时只过 1 层。参数已留但默认关闭。
- 首通投入门槛（不买够升级不许首通）：结构性死锁。每层的升级要用本层声望产出的货币买，而首通本身就是第一次声望，两者互为前提。
