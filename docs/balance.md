# 数值与平衡

本文记录 v9.0 的关键公式，方便后续调整。所有数值都可以在 `js/mod.js`、`js/layers/modpack.js` 中修改。

## 全局难度

```js
const DIFFICULTY = new Decimal(5.0)
```

- 原版层需求与升级价格使用 `dReq()` / `upgCost()`，全部 ×5.0。
- 模组层的 `cfg.requires` 是未乘难度的原始需求，`cfg.req = cfg.requires * 5.0` 是乘难度后的值，升级、设施造价与软上限都基于 `cfg.req`。
- 如果想让整体更难，把 `DIFFICULTY` 调到 6 或 10；如果只想改模组层，调整 `cfg.req` 的生成方式。

## 原版六层

| 层 | 声望需求（已乘难度） | 声望指数 | effect 指数 |
| --- | --- | --- | --- |
| 橡木林 | 75 原木 | 0.55 | 0.6 |
| 石矿洞 | 300 木板 | 0.50 | 0.5 |
| 铁矿脉 | 400 圆石 | 0.45 | 0.5 |
| 钻石层 | 500 铁锭 | 0.45 | 0.6 |
| 下界 | 300 钻石 | 0.50 | 0.6 |
| 末地 | 150 下界合金锭 | 0.50 | 0.7 |

- 需求在 `js/layers/overworld.js` / `js/layers/nether_end.js` 中通过 `dReq()` 写成上表数字；表中数值已是乘过全局难度 5.0 的最终需求，公式里不要再重复乘。
- v7.0 收紧了原版段：需求整体提高到原来的 1.5–3 倍，前四层声望指数下调 0.05，`effect` 指数全部下调 0.1。木板与圆石不再能靠早期无限叠乘把整条链一路滚穿。
- `effect` 指数同时用于深层反哺的折算，两条公式保持一致。

## 模组层需求

第 `i` 层（从 0 开始）：

```text
requires = 128 * 1.42^i
req      = requires * 5.0
exponent    = max(0.22, 0.44 - i * 0.007)
effectExp   = max(0.3, 0.62 - i * 0.01)
```

- 第 0 层 `req = 640`（`requires = 128`）。
- 第 29 层原始需求约 3.3e6，乘难度后约 1.7e7。
- 需求从 `3^i` 降到 `1.42^i`：取消硬上限后，本层资源可以无限累积，改用更平缓的需求曲线把增长摊到声望次数与首通施工上，而不是靠一个天花板截断。
- 声望指数从 0.44 平滑降到第 29 层的 0.237；0.22 的下限只在超过 30 层后才会触发，30 个模组层内不会出现突然变平的一整段。
- v7.0 放宽了后半段：需求增长从 1.45 放缓到 1.42，指数衰减从每层 0.009 放缓到 0.007，第 29 层的声望指数由 0.18 提高到 0.237。

## 深层反哺（基础产量）

第三层起，每层的 `everBest`（历史最高资源）会给原木基础产量提供永久加成：

```text
layerBonus = (everBest + 1) ^ (effectExp × 0.15) - 1
depthMult  = 1 + Σ layerBonus
每秒原木   = 基础产量 × 木板 effect × depthMult × 全局倍率
```

- `everBest` 单独记录，`layerDataReset` 不会清空，因此声望、级联重置与挑战都不会让深层加成失效。
- 各层加成线性相加而不是连乘：30 个模组层同时达到 1e6 资源时 `depthMult` 约为 60，不会把基础产量直接推到天文数字。
- 原版第三层起同样参与（i/d/n/e 的 effectExp 为 0.5/0.6/0.6/0.7，与各层 effect 指数一致）；木板与圆石已经通过木板 effect 和声望链影响原木，不重复计入。
- 顶部 HUD 只在 `depthMult > 1` 时挂出「深层反哺 ×N」标签。

## 首通施工

```text
need     = req * arch.time * 折扣
进度     = clamp(投入材料 / need, 0, 1)
收益系数 = 0.3 + 0.7 * 进度
```

- 材料来自上一层资源（`cfg.prev` 的 `points`），按 25% / 50% / 全部剩余 三档投入，最后一档自动补足；投入量记在 `player[层].construct`。
- 原型施工需求倍率：采集 0.9、科技 1.1、魔法 0.9、工业 1.0、探索 1.2。
- 25 号升级：`need *= 0.8`。
- 施工设施每级减少 3.85%（`0.5 / 13`），最多 13 级，第 13 级正好减少 50%。
- 主题特性「疾行」与主题核心（疾行类）：乘 0.92 / 0.985^级，6 号里程碑把特性折扣平方。
- 探索路线与 5 号里程碑：快路线减需求效果从 40% 提高到 60%；丰路线 `need *= 1.4`。
- 8 号里程碑（主题核心为疾行类）：`need *= 0.95`。
- 挑战只影响声望收益、软上限、自动产出与特性/核心，不改变施工需求。
- 施工未满也能提前声望，声望入账在软上限折算后再乘 `mpBuildGainMult()`，向下取整；满额 ≥1 时结果保底 1，避免提前声望拿 0。折扣只作用于声望结算（`game.js` 的 `doReset` 调用层的 `prestigeGainMult()`），`getResetGain()` 保持满额供层内自动产出使用。
- `canReset()` 只检查前置资源 ≥ `req` 且本次收益 ≥1；`mpBuildProgress()` 负责进度，`mpBuildDone()` 等价于进度满 100%。
- 每层首次声望后记为已通过（`player[层].prestiged`），此后该层不再检查施工、收益固定 100%；重置时保留这个标记，`construct` 随 `startData` 归零。
- 自动声望通过层的 `autoPrestigeReady()` 钩子等本轮施工完成才触发，不会为了提前收益主动重置。
- 施工没有跳过手段：v8.6 起移除了「施工券」，唯一的推进方式是投入上一层资源。投入会占用声望本金，声望本身仍要求上一层资源 ≥ `req`，投入后记得留足。
- 本轮第一次投满时记 `player[层].buildBonus`，声望收益额外 ×1.25；掉进度（押注失败）后这条奖励失效，需重新投满。

## 主动玩法与轮次变量

### 层专精（每层每轮一次）

| 专精 | 效果 |
| --- | --- |
| 产能 | 本层产量与自动产出 ×2.5 |
| 施工 | 本层施工材料需求 ×0.55（−45%） |
| 声望 | 本层声望收益 ×1.8、本层产量 ×0.9 |

- 数据在 `js/features.js` 的 `SPECIALIZATIONS` 与 `SPEC_GAIN` / `SPEC_WALL` / `SPEC_PRESTIGE`。
- 接入点：`specGainMult()` → `gainMult()`，`specPassiveMult()` → `passiveGeneration()`，`specWallMult()` → `mpBuildNeed()`，`specPrestigeMult()` → `prestigeGainMult()`。
- 选定后不可改选（`setSpecialization` 只在 `spec === 0` 时写入）；`spec` 在 `startData` 里，本层被重置或真转生时归零，等于每轮重新选一次。

### 点击连击

```text
每 3 次点击 +1 层，每层全局产量 +15%，最多 5 层（+75%）
30 秒不点击清零（按真实时间）
```

- 常量：`CLICK_COMBO_PER / STEP / MAX / KEEP`（`js/features.js`）。
- `clickComboMult()` 乘进 `computeGlobalProductionMult()`，所以「不点就掉产量」；点击本身仍受 `clickPower()` 支配。
- `clickSpeedMult() = min(10, sqrt(player.devSpeed))`，只在控制台调过加速时生效，正常游玩恒为 1。

### 裂隙（限时事件）

| 类型 | 90 秒内目标 | 奖励 |
| --- | --- | --- |
| 坍缩 | 点击 15 次 | 全局产量 ×2，持续 10 分钟 |
| 商队 | 3 次施工投入 | 触发层施工进度 +5% 需求（折算成材料） |
| 过载 | 手动购买 8 次 | 全局产量 ×1.5，持续 10 分钟 |

- 间隔 150–420 秒随机刷一个（`RIFT_GAP_MIN / RIFT_GAP_MAX`），窗口 90 秒，增益 10 分钟（`RIFT_BUFF_TIME`）。
- 错过只累加 `player.rifts.missed`，没有任何惩罚。
- 增益只有一格：刷新不叠加，强增益不会被弱增益覆盖（`riftBuffMult` 取当前值）。
- 计时全部用 `Date.now()`，与 `devSpeed` 解耦。
- 自动购买不推进「过载」（`js/game.js` 的 `autobuyUpgrades` 里用 `riftAutoBuying` 标记），其余手动操作都算。

### 施工分档与首满

- 投入按钮 25% / 50% / 全部剩余 三档（12 / 14 / 15 号 clickable），最后一档按剩余需求补足。
- 本轮第一次投满时置 `player[层].buildBonus`，声望收益额外 ×1.25。
- `prestigeGainMult() = 施工折扣 × 专精声望 × 首满 1.25 × 世界词条`，且首满那一项要求 `mpBuildDone()` 仍为真：押注失败把进度打到 85% 后，1.25 与满额收益一起消失。

### 押注（每层每轮一次）

```text
胜率 p   = 0.5 + 0.05 × 本层已完成挑战数（0–3，最高 0.65）
押注额   = 上一层资源 × 30% / 60% / 100%（向下取整）
赢       = 拿回 1.2/p 倍押注 + 施工进度 +10% 需求
输       = 押注归零 + 施工进度 −15% 需求（不低于 0）
期望     = p × 1.2/p − 1 = +20%
```

- 写在 `player[层].wagerUsed / wagerResult`，随 `startData` 每轮清零；`prestiged` 或挑战进行中不能押。
- 押注直接从 `player[cfg.prev].points` 扣，扣完仍要够 `cfg.req` 才能声望，所以 100% 押注有把本层卡死的风险 —— 这是设计上的赌。

### 世界词条（真转生三选一）

| 词条 | 效果 |
| --- | --- |
| 贫瘠 | 全层施工需求 ×1.3、声望收益 ×1.25 |
| 丰饶 | 全层施工需求 ×0.8、全局产量 ×0.85 |
| 静默 | 自动购买全部失效、全局产量 ×2 |
| 疾行 | 全层施工需求 ×0.75、声望收益 ×0.9 |
| 潮汐 | 全层软上限 ×1.3、全局产量 ×0.9 |
| 回响 | 声望收益 ×1.15、点击收益 ×0.5 |
| 徒手 | 点击收益 ×3、全局产量 ×0.6 |
| 失衡 | 声望收益 ×1.5、全层软上限 ×0.75 |

- `js/features.js` 的 `WORLD_MODS`；每次真转生领取后随机抽 3 条写进 `player.rebirth.modChoices`，选中的写进 `player.rebirth.mod`，一直生效到下次真转生。
- 只挂五类入口：`worldModReq()` → `mpBuildNeed()`，`worldModGain()` → `prestigeGainMult()`，`worldModProd()` → `computeGlobalProductionMult()`，`worldModCap()` → `mpSoftcap()`，`worldModClick()` → `clickPower()`，`worldModAuto()` → 自动购买开关。绝不改 `requires`、挑战条件与解锁条件，词条不可能把层锁死。
- 未选词条时所有倍率为 1，不影响开局；「贫瘠」的需求 ×1.3 会连带压低同一笔投入的进度收益，这是它的隐性代价。
## 软上限（收益递减）

本层资源没有存储上限，唯一的天花板是声望收益的软上限。

```text
softcap = req * arch.soft
```

| 原型 | soft 倍率 |
| --- | --- |
| 采集 | 0.14 |
| 科技 | 0.10 |
| 魔法 | 0.19 |
| 工业 | 0.15 |
| 探索 | 0.26 |

再乘：

- 2 号里程碑：softcap ×2。
- 23 号升级：softcap ×1.5。
- 上限设施（13 号）：每级 softcap +15%。
- 主题特性「稳固」与主题核心（稳固类）：×1.20 / ×1.06^级，6 号里程碑把特性部分平方。
- 科技「存储研究」：每级 +10%；探索「稳」路线：×1.25（5 号里程碑 1.375）。
- 当前挑战为薄雾时：×0.5；12 号挑战完成：×1.25。
- 8 号里程碑（主题核心为稳固类）：×1.2。
- 层机制：轮转、过载等按当前状态乘进软上限（见「层机制」一节）。

声望收益一旦超过软上限，超出部分按平方根折算。软上限只压缩单次声望的战利品，不限制 `points`、`best` 或累计资源，因此可以一直堆下去，只是越堆越慢。

## 重置范围

- 单次声望最多回退本层及下面 4 层（`RESET_DEPTH = 5`，`js/game.js` 的 `doReset`），更低的层与它们的点数、购买项、升级保持原样。
- 发起声望的本层不重置点数与升级，只把 `resetTime` 归零；点数、升级、设施被清空的是窗口内的更低层。
- 例如手动重置第 6 层会回退第 2–5 层，木板（第 0 层）、圆石（第 1 层）与原木 `player.points` 都保留；手动重置第 5 层则回退第 1–4 层。
- 每次声望会把回退下限写入 `player.resetFloor`；自动声望不会低于该下限（`autoResetFloor`），保留层不会被逐 tick 连锁重置，想重置更低层需手动声望。
- 挑战完成判定同样只在回退窗口内执行，窗口外的挑战不会被顺带完成。
- 窗口内已首通层仍由 `retainStartKit` 保留 12 号升级与 1 级生产设施。

## 声望收益

```text
gain = (前置资源 / req)^exponent
     * gainMult^gainExp
```

随后：

```text
if (gain >= softcap) gain = sqrt(gain) * sqrt(softcap)
gain = floor(gain)
```

`gainMult` 的来源：

- 11 号升级：×arch.upg2（2 / 2.5 / 3）。
- 13 号升级：×arch.upg3（3 / 4）。
- 15 号升级：主题签名倍率 ×`sig.mult`（7–10），逐层不同。
- 24 号升级：本层 ×1.5（同时解锁上限设施）。
- 0/3/4 号里程碑：本层各 ×1.5；7 号里程碑再 ×2；9 号里程碑（完成全部挑战）再 ×1.5。
- 增益设施：每级 ×arch.gain（1.08–1.15），最多 20 级。
- 21 号升级：全局产量 **+10%**（30 层全部购买后为 ×4，线性叠加，不再逐层相乘）。
- 下一层的 `effect()`：`(下一层资源 + 1)^effectExp`。
- 主题特性与原型机制（见下两节）；6 号里程碑使特性效果翻倍。
- 主题核心：按 `cfg.trait.core` 生效——产量/自动产出类每级 ×1.08，软上限类 ×1.06，施工需求类 ×0.985，全局产量类每级 +0.5%（线性叠加）；8 号里程碑再按核心类型给 ×1.25 / ×1.2 / ×0.95 / ×1.2 / +2%。
- 11 号挑战完成：本层 ×1.5。
- 层机制：专属或模板机制按当前状态乘进产量（见「层机制」一节）。
- 全局成就与旧层加成。

## 原型机制

| 原型 | 机制 | 数值 |
| --- | --- | --- |
| 采集 | 连续采掘 | 自动产出 ×`1 + 2 × 施工进度`；5 号里程碑把系数 2 提高到 3 |
| 科技 | 研究分支 | 算力：声望 +10%/级；存储：软上限 +10%/级；散热：自动 +15%/级；各 5 级 |
| 魔法 | 主动咒语 | 消耗 10% 资源，60 秒内 `gainMult ×5`，冷却 8 分钟（5 号里程碑 6 分钟） |
| 工业 | 设施联动 | 声望 `×(1 + 0.01 × (生产等级 + 上限等级))`；自动 `×(1 + 0.02 × 增益等级)`；5 号里程碑两项 +50% |
| 探索 | 远征路线 | 快：施工需求 ×0.6、收益 ×0.8；稳：软上限 ×1.25；丰：施工需求 ×1.4、收益 ×1.3；5 号里程碑使正向部分 +50% |

科技研究点按「前置资源超出需求的比例」计算：`1 + floor(5 × min(1, 前置资源 / req - 1))`，即每超出 20% 多 1 点，每次声望 1–6 点；5 号里程碑再 +1，最多 7 点。研究与路线状态写在 `player[层].research` / `player[层].route`，魔法计时写在 `spellUntil` / `spellReadyAt`；所在层被重置时随 `startData` 归零。

## 层机制

每层在原型机制之外还有 1 套层机制，全部乘进 `gainMult`、`passiveGeneration`、`mpSoftcap` 或 `mpBuildNeed`。前 6 层专属：

| 层 | 机制 | 数值 |
| --- | --- | --- |
| 暮色森林 | 迷宫探索 | 每次投入 12% 当前资源，最多 12 层：产量 ×`1 + 0.04 × depth`，自动 ×`1 + 0.02 × depth`，软上限 ×`1 + 0.01 × depth` |
| 植物魔法 | 魔力花圃 | 40 秒生长，收获 30 秒自动产出；每次收获产量 +3%，最多 10 次 |
| 工业时代 | 电压档位 | 低耗：产量 ×0.85、施工需求 ×0.85；标准：×1；超频：产量 ×1.6、软上限 ×0.85、施工需求 ×1.25 |
| 神秘时代 | 虚空凝视 | 开启：产量 ×1.35、施工需求 ×1.25、软上限 ×0.92 |
| 应用能源 | 网络优先级 | 存储优先：软上限 ×1.2；产量优先：产量 ×1.15 |
| 龙之研究 | 混沌风险 | 风险 0/1/2/3：产量 ×1 / ×1.08 / ×1.2 / ×1.4；软上限 ×1 / ×1 / ×0.92 / ×0.8；施工需求 ×1 / ×1 / ×1 / ×1.2 |

其余 24 层按 `MP_TEMPLATE_ORDER` 轮换 8 套模板，每套模板按层批次取 3 个变体之一（`math.floor((index - 6) / 8)`，写入 `cfg.mechV`）：

| 模板 | 变体 1 | 变体 2 | 变体 3 |
| --- | --- | --- | --- |
| 潮汐 | 缓潮：周期 60 秒、涨潮 30 秒、产量 ×1.45 | 快潮：周期 24 秒、涨潮 8 秒、产量 ×1.75 | 长潮：周期 50 秒、涨潮 35 秒、产量 ×1.36 |
| 轮转 | 三相：90 秒循环、每相 30 秒，产量 / 软上限 / 自动 ×1.35 | 双相：60 秒循环、每相 30 秒，产量 / 软上限 ×1.5 | 深耕：120 秒循环、每相 40 秒，产量 / 软上限 / 自动 ×1.4 |
| 回响 | 常响：产量 ×`1 + 0.05 × min(20, mechCount)` | 深响：产量 ×`1 + 0.03 × min(30, mechCount)` | 共振：产量 ×`1 + 0.04 × min(20, mechCount)`，自动 ×`1 + 0.02 × min(20, mechCount)` |
| 矩阵 | 常阵：每 6 级产量 +4%、自动 +2% | 密阵：每 4 级产量 +2.5%、自动 +1.5% | 重阵：每 10 级产量 +7%、自动 +3% |
| 赌局 | 小赌：押 8%，50% 收回 250%，45 秒冷却 | 稳局：押 5%，60% 收回 200%，30 秒冷却 | 豪赌：押 15%，50% 收回 240%，60 秒冷却 |
| 储备 | 常备：每秒存入 0.1%，上限 60% | 活期：每秒存入 0.12%，上限 30% | 定期：每秒存入 0.09%，上限 90% |
| 过载 | 常载：产量 ×1.35、自动 ×0.6、施工需求 ×1.1 | 微载：产量 ×1.2、自动 ×0.8、施工需求 ×1.05 | 暴力过载：产量 ×1.6、自动 ×0.45、施工需求 ×1.2 |

状态写在 `mechMode` / `mechOn` / `mechAt` / `mechDepth` / `mechCount`。除 `mechCount` 会在 `retainStartKit` 中保留外，其余字段随本层 `startData` 重置。模板机制不改变挑战条件、施工判定或设施造价。

| 丰饶 | 声望收益 ×1.12 | 本层产量 ×1.08 |
| 稳固 | 软上限 ×1.20 | 软上限 ×1.06 |
| 疾行 | 施工需求 ×0.92 | 施工需求 ×0.985 |
| 工程 | 设施造价 ×0.90 | 自动产出 ×1.08 |
| 博学 | 升级造价 ×0.85 | 本层产量 ×1.08 |
| 先驱 | 里程碑需求 ×0.80 | 软上限 ×1.06 |
| 涌动 | 自动产出 ×1.25 | 自动产出 ×1.08 |
| 共鸣 | 全局产量 +5%（该层解锁后计入线性加成） | 全局产量 +0.5% |

## 挑战

每层 3 个挑战按顺序解锁，进入时把本层 `points` 与 `best` 存到 `chSavedPoints` / `chSavedBest` 后清零，退出或完成时取挑战进度与原记录的较大值恢复。

挑战条件从以下模板中按层轮换（`MP_CHALLENGE_SETS`），名称随主题变化；11/12 号只使用不依赖升级或核心的条件，封存/熄核只放在 13 号，避免早期挑战被锁死。

| 条件 | 挑战期间 | 目标 |
| --- | --- | --- |
| 薄雾 | 软上限 ×0.5 | 1.0 × req |
| 断供 | 自动产出 ×0.25 | 1.5 × req |
| 迟滞 | 声望收益 ×0.6 | 1.2 × req |
| 封存 | 签名升级失效 | 1.0 × req |
| 失谐 | 主题特性失效 | 0.9 × req |
| 熄核 | 主题核心失效 | 1.0 × req |

完成奖励按槽位固定：11 号本层产量 ×1.5，12 号软上限 ×1.25，13 号自动产出 ×1.5。封存挑战要求已购买 15 号升级，熄核挑战要求已解锁主题核心（4 号里程碑）。

挑战完成状态写入 `player[层].challenges[11..13]`，每个只能完成一次。

## 层间任务

任务不单独存完成标记，每个任务的目标都从只增不减的存档状态推导：

| 任务 | 数据来源 | 目标 | 奖励 |
| --- | --- | --- | --- |
| 初见模组海 / 五层连穿 / 十层工业带 / 二十层远征 / 三十层全图 | `player[层].prestiged` 计数 | 1 / 5 / 10 / 20 / 30 | +4% / +6% / +8% / +10% / +12% |
| 挑战者 / 挑战收割机 | `challenges[11..13]` 已完成的槽位数 | 10 / 40 | +4% / +6% |
| 单层全清 / 五层全清 | 3 个挑战全部完成的层数 | 1 / 5 | +5% / +8% |
| 自动化网络 | `player.shop.owns` 中已购买的层数 | 10 | +6% |
| 深层回响 | `depthBaseMult()` | ×2 | +5% |
| 声望长跑 | `player.quests.stats.prestiges` | 100 | +8% |
| 模组海征服者 | 以上 12 个任务的完成数 | 12 | +10% |

已完成任务的奖励线性相加，由 `globalProductionMult()` 末尾乘入：

```text
全局倍率 = (原本各来源的乘积) × (1 + Σ 已完成任务奖励)
```

- 全部完成合计 **+92%**，作为一次乘算；不会像 21 号升级那样逐层叠乘。
- 声望计数只在真实声望时 +1（`onPrestige`），挑战进入与退出不计入；旧存档首次载入按已首通模组层数回填一次。
- 其余任务目标均为单调状态，声望与级联重置不会让进度或奖励回退。

## 转生（模组记忆）

30 个模组层全部首通后，侧栏解锁「模组记忆」。转生是第二层循环：清空数值进度，把累计声望换成永久记忆升级。

```text
总记忆   = floor(sqrt(累计模组声望次数) × 1.5)
本次可领 = 总记忆 - 已领取
可用记忆 = 已领取 - 已投入
```

- 累计声望直接读 `player.quests.stats.prestiges`，不新开计数器；旧存档的任务回填同时作为转生起点。
- **真转生**：v8.6 起除模组记忆层外，所有层（含成就、层间任务、商店）全部回到 `startData` —— 资源、升级、设施、研究、路线、法术、层机制、首通标记 `prestiged`、`everBest` 与 `player.resetFloor` 一并清零，从 `getStartPoints()` 的原木重新开始。
- 因为层间任务会被清空，累计声望额外记一份基线 `player.rebirth.basePrestige`：`rebirthPrestigeCount() = basePrestige + quests.stats.prestiges`，领取时把当前值写回基线，记忆总额因此只增不减。
- 解锁条件改为「30 层全首通 **或** 已领过记忆」，否则真转生清掉 `prestiged` 后记忆页会消失。
- 转生后不再有「已首通但本轮未施工」的状态（`prestiged` 已清零），原先的熟路减半（`REBIRTH_WALL_MULT`）不再生效；施工需求只会被 25 号升级、施工设施与「记忆熟路」降低。
- `construct` 随 `layerDataReset` 归零；施工不依赖时间，重建速度取决于投入材料的速度。
- 领取与购买都只增不减：记忆不会因转生减少，升级也不随转生重置。

| 升级 | 每级效果 | 级数 | 造价 |
| --- | --- | --- | --- |
| 记忆洪流 | 全局产量 +10%（加法） | 10 | `2 × 1.55^level` |
| 记忆扩容 | 模组软上限 ×1.06 | 8 | `2 × 1.55^level` |
| 记忆起手 | 转生后每层直接给 1 级生产设施 + 12 号升级 | 6 | `2 × 1.55^level` |
| 记忆捷径 | 自动声望阈值 −0.05×，最低 1.0× | 10 | `2 × 1.55^level` |
| 记忆熟路 | 施工需求 −6% | 8 | `2 × 1.55^level` |
| 记忆丰产 | 模组层声望收益 ×1.15 | 8 | `2 × 1.55^level` |
| 记忆自动 | 模组层自动产出 ×1.25 | 6 | `2 × 1.55^level` |
| 记忆深潜 | 深层反哺指数 +0.02 | 6 | `2 × 1.55^level` |

- 单条线造价合计：10 级 320 记忆，8 级 134 记忆，6 级 52 记忆；八条线全部升满需要 **1198 记忆**。
- 记忆洪流乘进 `globalProductionMult()`，自身 10 级提供 +100% 的加法内部倍率。
- 记忆扩容乘进 `mpSoftcap()`，只影响模组层。
- 记忆起手只在转生重置时发放生产设施等级；之后正常声望仍按原有启动套件保留 12 号升级与 1 级生产设施。
- 记忆捷径只下调自动声望的判定阈值，不改变商店价格、自动购买或回退下限。
- 记忆熟路乘进 `mpBuildNeed()`，与 25 号升级、施工设施同为乘法折扣，三者叠满约剩 `0.8 × 0.5 × 0.52 ≈ 21%` 需求。
- 记忆丰产乘进模组层的 `gainMult()`，记忆自动乘进 `passiveGeneration()`，都只作用于模组层，不影响原版六层。
- 记忆深潜加在 `computeDepthBaseMult()` 的指数上（`exp + 0.02 × 级数`），满级把 30 层的反哺斜率整体抬高约 13%。
- 记忆总额为 `floor(sqrt(累计模组声望) × 1.5)`，按声望次数开方，鼓励「攒够再转生」而不是频繁转生。

## 升级与设施造价

升级造价：

```text
cost = req * factor * arch.cost * (trait.upgrade ^ (6 号里程碑 ? 2 : 1))
factor = [0.002, 0.004, 0.008, 0.015, 0.03, 0.05, 0.09, 0.14, 0.22, 0.34]
```

升级造价是函数，6 号里程碑会实时把「博学」类折扣翻倍。

设施造价：

| 设施 | 基础系数 | 增长 | 上限 |
| --- | --- | --- | --- |
| 生产 | 0.01 × req | 1.8^level | 无 |
| 增益 | 0.02 × req | 1.9^level | 20 |
| 上限（软上限） | 0.03 × req | 2.0^level | 无 |
| 施工 | 0.04 × req | 2.1^level | 13（降低施工需求最多 50%） |
| 主题核心 | 0.05 × req | 2.2^level | 10 |

增益设施最多购买到 20 级（`Decimal.pow(arch.gain, min(level, 20))`），避免单层声望倍率无限叠乘；施工设施最多 13 级，降低施工需求的效果在 50% 封顶。「工程」类特性会乘进所有设施造价，6 号里程碑同样翻倍。

科技层的 15–17 号研究分支不花本层资源，改用研究点：每级成本依次为 1、2、3、4、5 点，最多 5 级。

## 自动化产出

```text
passive = 生产设施等级 * arch.passive
        * (14 号升级 ? 1.5 : 1)
        * (1 号里程碑 ? 2 : 1)
        * 特性/主题核心的自动产出倍率
        * (13 号挑战完成 ? 1.5 : 1)
        * (当前挑战为断供 ? 0.25 : 1)

每秒实际产出 = passive * 本层声望收益（resetGain）
```

`passive` 只是系数，`generatePoints` 会再乘一次当前的声望收益，所以设施产出的真实速度与声望收益同步增长；界面显示的每秒产出就是乘完后的数值。

原型的 `passive`：采集 0.06、科技 0.04、魔法 0.06、工业 0.05、探索 0.04。

## 自动化阈值与启动套件

```text
自动声望条件：canReset && baseAmount ≥ autoPrestigeMult() × requires
autoPrestigeMult() = 1.5 - 0.05 × 记忆捷径等级（最低 1.0）
每个 tick 最多自动声望一次
```

- 默认阈值常量是 `js/game.js` 中的 `AUTO_PRESTIGE_MULT = 1.5`，实际取值经 `autoPrestigeMult()` 叠加转生「记忆捷径」；调高常量会让自动声望等到更多资源，调低则更频繁地重置。
- 自动声望受商店顶部的总开关 `player.shop.autoPrestige` 控制；任意挑战进行中跳过。
- 已首通层被回退时，`retainStartKit` 会保留 12 号升级与 1 级生产设施，避免每次重置后重新买第一级。
- 自动化价格在 `js/layers/shop.js` 的 `SHOP_PRICE_MULT = 2`；改这个值即可整体调整自动化造价。

## 调整建议

- **想更快**：降低 `requires` 的底数 128，或提高 `arch.passive` / `arch.gain`。
- **想更慢**：提高 `DIFFICULTY`、降低 `exponent`、调高施工需求系数 `MP_BUILD_RATIO`。
- **想更强调收益递减**：降低 `arch.soft` 或 `softcapPower`（当前固定 0.5）。
- **想压缩层数**：减少 `MOD_THEMES` 条目即可，工厂与成就会自动适配。

修改后建议至少验证：

1. 第一层能否在投入材料完成施工后正常声望。
2. 软上限是否只压缩单次声望，而不阻止 `points` / `best` 继续增长。
3. 下一层是否自动解锁。
4. 成就墙数量是否仍与 `ACH_TOTAL` 一致。
